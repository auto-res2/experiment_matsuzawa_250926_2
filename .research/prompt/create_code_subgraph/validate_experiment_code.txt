# Experimental Design

## Experiment Strategy
=================================================
EXPERIMENT 1 – Real-World Compute–Savings Benchmark
-------------------------------------------------
Goal
• Show that P-AUTOMATA reaches the same or better best-validation/test accuracy than the AUTOMATA baseline while reducing GPU time.
• Demonstrate the automatic growth of the subset fraction and its impact on ranking stability.

Set-up
• Datasets & models (single A100, single seed per run, 3 runs for stats):
  – CIFAR-10 + ResNet-18 (30 epochs max).
  – SST-2 + 1-layer LSTM (10 epochs max).
  – ImageNet-1k (subset 200 classes, 90 epochs) + MobileNet-V2 to stress larger data.
• Methods compared:
  a) AUTOMATA-Fixed-05  (f = 0.05)
  b) AUTOMATA-Fixed-10  (f = 0.10 ⇒ default in paper)
  c) AUTOMATA-Fixed-30  (f = 0.30 ⇒ upper bound)
  d) Progressive-AUTOMATA (f0 = 0.05, γ = 2, ϵ = 0.30, fmax = 0.30)
• Hyper-parameter space identical to original paper; 100 configurations; ASHA η = 3.
• Metrics recorded per run:
  1. Wall-clock GPU hours until ASHA terminates.
  2. Best validation accuracy and final test accuracy.
  3. Subset fraction f chosen at every rung.
  4. Rank-instability Δt.

Success Criterion
P-AUTOMATA must
• match or exceed the best-fixed-10 validation/test accuracy within confidence bounds (±0.2 %).
• use ≥25 % less GPU hours than Fixed-10 on CIFAR-10 & SST-2; ≥15 % on ImageNet-1k.
• exhibit monotonic decrease of Δt as f grows (empirical proof of bias–variance trade-off).

What It Demonstrates
Shows that (i) the adaptive schedule avoids under-sampling (compared to Fixed-05) and over-sampling (compared to Fixed-30), (ii) delivers state-of-the-art accuracy at lower cost, and (iii) the instability signal truly governs f.

=================================================
EXPERIMENT 2 – Ablation & Hyper-parameter Robustness Study
---------------------------------------------------------
Goal
Is the heuristic truly parameter-free in practice?  Test sensitivity to f0, ϵ and γ and verify each component is necessary.

Set-up
• Focus on CIFAR-10 + ResNet-18; 50-configuration search to keep runs cheap (≈6 GPU h each on A100).
• Variants (all other knobs identical):
  1. FULL DATA – AUTOMATA with f = 1.00 (upper baseline).
  2. P-AUTOMATA (default).
  3. No-Growth: progressive logic disabled (f stuck at f0 = 0.05).
  4. No-Instability-Check: always double f every rung (simulates γ-growth w/out Δt gate).
  5. P-AUTOMATA with ϵ ∈ {0.1, 0.5}.
  6. P-AUTOMATA with γ ∈ {1.5, 3}.
• Metrics: best validation accuracy, GPU hours, final f, and Kendall-τ correlation between ranking at last rung vs FULL DATA.

Success Criterion
• Default P-AUTOMATA should be within 1 % top-1 accuracy of FULL DATA using ≤40 % of its GPU hours.
• No-Growth loses ≥2 % accuracy (shows too-small subsets fail).
• No-Instability-Check wastes ≥25 % more GPU than default with no accuracy gain (shows gate is needed).
• Variations of ϵ, γ alter compute by <10 % and accuracy by <0.5 % (robustness).

What It Demonstrates
Pinpoints which parts of the heuristic matter, proves stability threshold is crucial, and shows wide tolerance to hyper-parameter choices—highlighting the method’s plug-and-play nature.

EXPERIMENT 3 – Large-Scale Hyper-Parameter Optimisation at Scale
----------------------------------------------------------------
Goal
Demonstrate scalability to modern, expensive models where subset selection is most valuable.

Set-up
• Task: Fine-tune BERT-Base on GLUE-MNLI (393 k examples) for 3 epochs.
• Search space: learning rate, warm-up steps, batch size, weight decay, dropout (≈5D).
• Budget: 400 configurations.
• Scheduler: Population Based Training (PBT) inside AUTOMATA (already supported) – shows compatibility with non-ASHA schemes.
• Fixed baselines: f ∈ {0.05, 0.10, 0.30}.
• Progressive-AUTOMATA: f0 = 0.02, γ = 2, ϵ = 0.25, fmax = 0.30.
• Hardware: 8 × A100 80 GB; each worker fine-tunes one config; search lasts ≤24 h.
• Metrics
  – Best validation accuracy on MNLI-m.
  – GPU hours consumed per discovered Pareto-optimal config.
  – Throughput (# configs completed / wall-clock).

Success Criterion
• P-AUTOMATA finds a configuration within 0.3 pp of the best validation accuracy achieved by any fixed-fraction run but consumes ≤60 % of the total GPU hours.
• Time-to-first-good-config (<85 % of peak accuracy) is ≤40 % of the time for Fixed-10.
• Subset fraction grows to f≈0.15 at late stages, confirming adaptivity.

What It Demonstrates
Highlights that the method scales to billion-parameter optimisations, integrates with more sophisticated schedulers (PBT), and drastically accelerates exploration where each full-data evaluation is expensive.

## Experiment Details

EXPERIMENT 1 – Real-World Compute-Savings Benchmark
================================================================================
1.  Data, Models & Baselines
   • CIFAR-10 (50 k train / 10 k test, 32×32 RGB)  →  ResNet-18 (11.2 M params)
   • SST-2 (67 k train / 872 dev / 1.8 k test, bin. sentiment)  →  1-layer Bi-LSTM + max-pool (3.1 M params)
   • ImageNet-1k-200 (first 200 WordNet synsets, 256×256, ≈250 k imgs)  →  MobileNet-V2 (3.5 M params)
   Baseline variants: AUTOMATA-Fixed-05 / 10 / 30.  Proposed: Progressive-AUTOMATA (P-AUTOMATA).

2.  Pre-processing
   • Image tasks: Random-resized-crop (224² for ImageNet-200, 32² for CIFAR) → RandomHorizontalFlip → ToTensor → Per-channel mean/std normalisation.
   • SST-2: Lower-case, strip HTML, tokenizer = spaCy-en_core_web_sm, max_len=64 tokens, vocab built on train only (min-freq=2), OOV=UNK.

3.  Splits & Folds
   • CIFAR-10: Train/Val/Test = 45 k / 5 k / 10 k.  Stratified by class.
   • SST-2: Original dev used as validation, test held-out.  No cross-validation.
   • ImageNet-200: 90 % / 10 % split over official train, official val ⇒ test.

4.  Search Space  (identical to AUTOMATA paper)
   learning-rate ∈ [1e−4, 1e−1] (log-uniform)
   batch-size ∈ {64, 128, 256}
   weight-decay ∈ [1e−6, 1e−3]
   dropout ∈ [0, 0.5] (text only)
   momentum ∈ [0.6, 0.95] (image only)

5.  Scheduler & Budget
   • ASHA with η = 3, max-epochs = 30 (CIFAR), 10 (SST-2), 90 (ImageNet-200) → rungs at {1, 3, 9, 27} / {1, 3, 9} / {3, 9, 27, 81}.
   • 100 configurations, 3 seeds (SEED = {17, 29, 43}).

6.  Run Protocol
   a) Start subset-fraction f = constant (baselines) or f0 = 0.05 (P-AUTOMATA).
   b) Inside each ASHA rung call GradMatchPB(dataset, fraction=f) every epoch.
   c) Adapt f using Δt heuristic (ϵ=0.30, γ=2, f_max = 0.30).
   d) Track wall-clock by NVIDIA nsys; memory via torch.cuda.max_memory_allocated.

7.  Repetition, Aggregation, Selection
   • 3 seeds → report mean ± std.
   • Inside a seed choose model snapshot with best validation accuracy (early-stop patience = 5 epochs).  In case of tie pick lower wall-clock.

8.  Metrics
   Primary:  Best-val-acc, Test-acc, GPU-hours.
   Secondary:  Δt per rung, FLOPs/iter, max VRAM, bootstrap 95 % CI of accuracy, energy kWh (via NVIDIA-SMI power draw).

9.  Robustness Checks (post-hoc, same weights)
   • CIFAR-10-C (15 corruptions × 5 severities) → mCE.
   • SST-2 OOD:  IMDB movie reviews (binary) re-tokenised identically → accuracy.
   • ImageNet-C-200 (subset) → mCE.

10. Hyper-parameter Importance
    – Use fANOVA on training logs; visualise interaction of lr × batch, lr × f.

11.  FLOPs & Cost Estimation
    – ptflops package per forward pass × observed #batches.
    – Spot price AWS p4d.24xlarge = 32 USD/h → compute cost.

12.  Reference Code Snippet (PyTorch-like)
```python
from automata import GradMatchPB
from ray import tune

def train_one(cfg, datamodule, subset_fraction):
    model = build_model(cfg)
    criterion, opt = nn.CrossEntropyLoss(), SGD(model.parameters(), lr=cfg['lr'], momentum=cfg['mom'])
    trainset = GradMatchPB(datamodule.train, fraction=subset_fraction)
    loader = DataLoader(trainset, batch_size=cfg['bs'], shuffle=True, num_workers=8, pin_memory=True)
    for ep in range(cfg['epochs']):
        for x,y in loader:
            opt.zero_grad(); model(x).loss(y).backward(); opt.step()
```
